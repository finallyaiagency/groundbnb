# M1-01B server session boundary

Date: 2026-10-07. Audit base: 3e4463e. Scope: server-only identity reader, not an account/profile persistence or login UI pass.

The pinned official `@neondatabase/auth@0.5.0-beta` SDK reads fresh managed sessions. It receives only the environment's isolated app token after configuration validation. Production/recovery activation, foreign issuers, wrong cookie namespaces, missing signing secret, unsafe email/jobs/dispatch settings and ambiguous deployment environment refuse contact. Expired, unverified or mismatched identities are rejected. The internal result contains issuer/subject only, granting no role, MFA or application account status. `/api/account/session` returns only authenticated/category with private no-store caching and remains off unless `GROUND_LOGIN_MODE=session-check` is explicitly configured. The SDK cache bypass requires the string `true` in this installed version; the real-SDK serialization regression tests this behavior.
