## Canonical profile dictionary and typing

Section 11.3 is the field authority. Choice values are the exact English labels/catalogs in frozen Section 9 and the intake choice definitions; do not invent aliases or persist display prose in place of a typed value. Multi-choice fields are deduplicated arrays retaining displayed order. Store each intake answer's `value`, `answered`/unset state, `scope`, and `updatedAt`. For an unanswered scalar use `null`; for an unanswered list use `[]` with `answered=false`. An explicitly cleared list is `[]` with `answered=true`. Unknown numeric values remain null, never zero. Keep user-entered home text even if resolution fails; `homePoint` then stays null and the UI shows the resolution warning.

Updating an account default marks dependent existing estimates stale; it never silently changes/reorders a confirmed route or reservation.

## Save, merge, and export contract

- Authenticated session provides ownership. Every mutation carries a stable operation ID, profile entity ID, expected revision, and validated typed field patch. Reject unknown keys and client owner/account IDs. Return operation ID, incremented revision, saved time, and canonical changed profile only after durable commit.
- A repeated operation ID with identical input returns its original result without incrementing revision; reuse with different input fails. On stale revision, return latest revision and field-level comparison. Offer reload latest, keep draft for comparison, or reapply selected changes with a new operation ID and latest revision. Never blind-overwrite.
- Autosave text after 600 ms idle; blur/Save flushes. Serialize profile writes. On timeout, query operation status before retry. Uncertain results preserve the exact draft and operation for explicit retry. Show human-readable failure, retryability, and request ID; success appears only after server acknowledgment and visible state agree.
- Account switch/sign-out clears all visible and browser-cached private data immediately, cancels pending writes, prevents prior-account responses/drafts from reaching the next account, and ignores late responses by account generation. No credential or profile `localStorage` cache. Account A→B→A tests must not flash foreign values.
- Profile review renders unset values as “Not specified”; categories and completion derive from the canonical profile, not a separately mutable view model. Intake, Profile, Planner defaults, and AI-edited profile fields must converge. AI profile context is readable prose, not a raw field dump. Quote selection/clear/removal must not delete structured fields or regenerate a user-removed note from old summarized history.
- Profile export uses the Section 11.22 native envelope: UTF-8 JSON `{format:"groundbnb", formatVersion:1, kind:"profile", exportedAt, profileFields, profileNotes}`. Show the sensitive-field preview before download; include only permitted dictionary values/notes and no auth cookies, secrets, ownership grants, provider consent, or raw chat. Home location and personal quotes are opt-in transfer fields.
- Structured import needs no AI. Parse and validate the same envelope; preview changes before writing. Default merge preserves existing values, shows before/after per field, and changes only fields the user selects. Pasted readable text may be offered through the import preview; uncertain parsing requires selected-field review, assisted interpretation consumes ordinary AI allowance, and manual entry remains available when AI is unavailable. Reject or visibly ignore attempted authority fields (owner, auth, plan, admin, payment, session, provider consent); never modify the legacy service.
- Calendar export summary appears only when actual optional calendar records exist. Never fabricate an empty/unknown calendar as confirmed data. Detailed PDF layout/content acceptance is ACC-05's full separate gate; this packet's profile export acceptance is the native transfer envelope and review/merge path.
