## Browser acceptance

1. **Manual records and unknown values.** Add a uniquely named synthetic vehicle/vessel with a type and no fuel-use value or unit, plus a uniquely worded synthetic personal note. Save through the ordinary profile UI, confirm visible success only after acknowledgment, reload the profile, and verify the canonical record arrays show the saved records. Blank fuel use must remain unknown; it must not display or persist as zero. Inspect the bounded save request and canonical response to confirm the client sends no owner/account/provenance authority and the note returns with server-assigned user origin.
2. **Native export review.** Open profile export and inspect the preview before downloading. Verify the default envelope contains only supported profile fields and excludes home data and notes unless explicitly opted in; opt in to notes only after checking the synthetic note preview. Download and retain this synthetic test file only within the run evidence. Do not treat an export preview as permission to include resolved/provider location data or authority fields.
3. **Tombstone behavior.** Remove the newly created note through the UI and save. Reload and verify it remains marked removed and is absent from active note summaries and a fresh export preview. Do not attempt to unremove it with the same ID; retain the earlier downloaded file for the import check below.
4. **Revision conflict.** In two tabs for the same synthetic account, stage distinct changes from one canonical revision. Commit one tab first, then save the stale tab. Verify the UI shows a conflict with both current and proposed record values, does not report a false save, and requires explicit review. Reapply only the selected synthetic change against the latest revision, confirm a new operation succeeds, and reload to verify both intended changes. If the UI cannot preserve the stale draft or safely resolve the conflict, stop and preserve evidence; do not repeat writes blindly.
5. **Selective native import.** Import the previously reviewed file through the ordinary preview. Confirm the preview identifies only selectable profile fields/notes and clearly separates any review-only home-location data. Change one synthetic profile value, then select only the earlier value for that field from the file; leave a second changed field unselected. Select the note for import. Confirm the merge, then reload: the selected field should match the imported value, the unselected field should retain its current value, the selected text should appear as a new user note, and the original note ID should remain tombstoned. Verify no owner, authentication, plan, role, payment, session, or provider-consent data is selectable or written. If selected notes cannot be persisted atomically with the selected fields, do not apply a partial combined merge; preserve the preview and stop.

Each failed/ambiguous write preserves its original operation for status review. Do not invent success from a proxy event, UI draft, offline test, or operator SQL script. This packet does not add a deliberate response-loss injection; that is a separate acceptance gate.
